# Contributing

Thanks for helping. This is a small project maintained in spare time, so a short issue
describing the problem is welcome before a large pull request.

## Before you start

- **Security problems** go to a [private advisory](SECURITY.md), not a public issue.
- **No installation-specific data** in anything you commit or post: no hostnames, IP
  addresses, personal data or real invoices. Redact logs and screenshots first.
- The app has no login of its own. It must only ever be published behind forward-auth.
- It only touches `expenses.*` and reads TeslaMate's `cars`, `positions` and
  `charging_processes`. Never write to a real TeslaMate database while developing.

## Set up

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
scripts/dev.sh up          # a dev stack with its own test database
```

`scripts/dev.sh` only ever reads from TeslaMate, and blanks latitude, longitude and
elevation when it copies positions. Don't copy more than that.

## Making a change

1. One feature or fix per pull request.
2. Write the failing test first, then the fix.
3. Run both test suites before you open the pull request:

   ```bash
   .venv/bin/python -m pytest -q    # needs docker; starts a throwaway Postgres
   scripts/dev.sh test-browser      # Playwright, real Chromium
   ```

4. After a UI or dashboard change, look at the screenshots in `.dev/screenshots`.
5. Fix linter findings (Ruff, Bandit, Hadolint) in the code where a small change removes
   them. For a reviewed exception, excuse that one line and give the reason, for example
   `# nosec B603 - why`. Don't add project-wide ignores.
6. Add a line under **Unreleased** in [CHANGELOG.md](CHANGELOG.md), and say if installers
   must do anything to upgrade.
7. Update the pages in `docs/` that your change affects. A new or changed screen needs a
   screenshot marker (see "Documentation and screenshots" in `docs/development.md`), and no
   screenshot or example may show real data.
8. Australian English in docs and UI.

## Things not to edit by hand

- `db/teslamate-schema.sql` is generated by `scripts/dev.sh schema`.
- `tmexpenses/schema.sql` must stay idempotent. If you add tables or columns, also update
  `db/grants.sql` and keep `scripts/provision-db.sh` working (`SKIP_MIGRATE=1`).

## OneDrive changes

Anything touching OneDrive needs a run against a real account before it's done:
`scripts/dev.sh onedrive-link`, then `scripts/dev.sh test-browser --onedrive`. Use a test
folder, never one holding real invoices, and never commit the saved sign-in file.

## Releases

Maintainers tag releases. Version numbers and the candidate-to-stable steps are in
[RELEASING.md](RELEASING.md).
